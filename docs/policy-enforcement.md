# Python policy enforcement

**Connected to scoped broker execution.** Pure evaluator, SQLite journal,
verified-fact gateway, HTTP recovery, issue/section lifecycle, review provenance,
Unix RPC, stdio MCP client, compatible CLI routing, Linux isolation launcher
implemented. Existing sandbox/revision/receipt guards retained and strengthened.
`RequestGate` stays sole runtime pacing authority; no hidden retry daemon.

Deployment: `docs/broker-deployment.md`. Local namespace/adversarial tests pass;
running OpenCode/credentials/services not reconfigured. Strict guarantees require
trusted installation + whole-tool-process isolation. Broker is optional: default
CLI uses unchanged external Pywikibot authentication and existing guards, no new
socket/token required. Not capability-authenticated execution; missing strict
deployment alone not publication blocker. Explicit broker settings remain fail-closed.

## Contract

```python
from mgwiki_editor.policy import Facts, NetworkFacts, Operation, Request, Role, evaluate

decision = evaluate(
    Request(Operation.READ_SOURCE, Role.COORDINATOR),
    Facts(network=NetworkFacts(endpoint_permitted=True, next_request_at=0)),
    now=1615,
)
assert decision.outcome == "ALLOW"
report = decision.as_dict()
```

Example supplies fixture facts, not verified observations. Caller can construct
roles/booleans. Types are not capabilities; ALLOW is not an execution token.
Gateway authenticates role/run intent, collects facts, durably reserves
operations, revalidates at effect boundary, and enforces decisions. Direct shell or
editable Python can bypass library checks; isolation remains required.

- Closed operations, roles, schema; frozen dataclasses/tuples; strict enum/type
  validation. Raw strings/dicts, mutable collections, boolean integers, NaN,
  infinity, negative/out-of-range timestamps rejected. Unix seconds through year
  9999 supported. No coercion, eval, network, data-file I/O, sleep, or clock reads.
- All time comes from caller. `history_verified`/`clock_verified` are obligations
  on runtime controller, not evidence generated by evaluator.
- Known failed check -> DENY; missing evidence/deadline -> DEFER; otherwise ALLOW.
  DENY takes precedence. `next_eligible_at` is maximum known deadline, not promise
  that missing evidence will appear. No retry deadline advertised on denied request.
- Findings retain stable rule IDs, reasons, required evidence, policy version.
  Reasons do not echo source text, arbitrary errors, or credential values.
- `transition()` checks topology only; no permission, mutation, observation, or
  review grant. Invalidated work returns to pinned for targeted revalidation;
  unconfirmed/confirmed save jobs cannot be reused for another submission.
- Preview parse may use HTTP POST yet remains read-only. Generic retry operation
  cannot relabel publish/reconciliation as safe read. Rendering requires sandbox.
- Reconciliation read does not require passing editorial/publication gates;
  requires exact target, unconfirmed receipt/stage, and permitted paced read.
- Open source issues never fail a gate. Separately reported material blockers do.
  Review-recorded facts are attestations, not proof of neutrality/meaning/fluency.
